## 0. Как работать по этому плану

- Один пункт (`Pn.m`) = одна ветка от `agent-flow-v2` (или от `main` после её слияния), один PR, один осмысленный коммит. Не объединяй пункты из разных фаз в один PR.
- Перед началом пункта прочитай указанные файлы целиком, не только цитируемые строки.
- После каждого пункта: `npm run check`. Если пункт трогает SQL, репозитории, миграции или транзакции: ещё `npm run test:e2e` (нужен Docker).
- Новая миграция = новый номер `00NN_*.sql`; существующие миграции не редактировать.
- `.env` не читать и не менять. Конфигурация только через `.env.example` и `src/config.ts`.
- Соблюдай инварианты из `AGENTS.md`: workspace-изоляция, консент на границе провайдера, мутация + журнал в одной транзакции, логи без текста сообщений.
- Если пункт меняет поведение для пользователя или оператора, обнови `README.md` / `MANUAL_ACTIONS.md` / `docs/DEPLOYMENT.md` в том же PR.
- Порядок фаз обязателен для фаз 0 и 1. Внутри остальных фаз пункты независимы, если не указано «после Pn.m».
- Каждый пункт имеет критерий приёмки. Пункт не закрыт, пока критерий не выполнен и не проверен тестом или командой.

## 1. Что сохранить (это работает хорошо)

- `src/core/` чистый: не импортирует ничего снаружи, тестируется отдельно. Не ломать.
- Транзакционная модель действий: один `action_group` + журнал + блокировки `FOR UPDATE ORDER BY id` в одной транзакции, внешних вызовов внутри транзакций нет.
- Контракт агента v2 (`src/core/ai-contract.ts`): 9 действий, короткие id `t1/g2/m3`, один `intent`, риск считает сервер.
- `src/chat/turn-errors.ts`: 39 кодов ошибок × 3 языка, каждый говорит, что пользователь может изменить.
- `src/core/applied-report.ts`: отчёт только по реально сохранённому, с датой до/после.
- `src/core/card-details.ts`: фильтрует поля модели, которые пересказывают заголовок.
- Логи через `safeError`/`safeMessageMetadata`: тела сообщений только как длина + sha256.
- Никакого `parse_mode` в Telegram: класс ошибок экранирования отсутствует.
- `callback_data` всегда ≤ 64 байт, uuid проверяется регэкспом.
- `scripts/backup-compose.sh`: атомарная публикация, проверка расшифровкой перед публикацией.

## Статус

`npm run check` — 220 core + 218 app тестов, `npm run test:e2e` — 53. Порог покрытия в `.c8rc.json` опускать нельзя.

Осознанно не сделано, чтобы это не искали заново:

- `action-mutations.repository.ts` не разрезан: там один шаг = одна транзакция, и деление без риска не выходит.
- Репозитории не вынесены из `AccessService`, `reminder-*`, `briefing-*`: удаление аккаунта, подавление доставок и аудит — одна транзакция, обёртка её разорвала бы.
- `briefing-content` и `reminder-queue` продолжают звать `telegram-ui`: это путь доставки в Telegram, а не утечка представления в домен.
- Rate-limit не учитывает in-flight: обновления одного чата и так строго последовательны (`sequentialize`), гонка возможна только между живым ходом и `AiRetryService`.
- `TypeScript 7` — см. ниже.

## Что осталось

**Инфраструктура (проверено на сервере 2026-09-05):**

1. **Off-site бэкапы.** Локальный стопгап работает: ключ в `/home/deploy/ipsycho-secrets/backup.key`, cron 03:15 (7 дневных + 4 недельных), первого числа — проверка восстановления в одноразовый контейнер. Проверено вживую (`backup_ok … offsite=no`, `restore_check_ok … tables=26`). Но копии и ключ шифрования лежат на той же машине, что база: потеря диска — потеря всего. Нужен bucket S3-совместимого хранилища и ключи; дальше достаточно дописать `S3_BACKUP_URI` в строку cron.
2. **Сверка цен провайдера.** `AI_PRICING_JSON` помечен `revision: 2026-09-05`. При смене модели или тарифа расчёт молча останется по старым числам.
3. **Ручные проверки `MANUAL_ACTIONS.md`** — требуют живого Telegram-аккаунта.

**UX (аудит 2026-09-05, найдено десятью агентами и перепроверено; исправленное см. `docs/AGENT_FLOW.md` §9з):**

4. **Пропуск повторяющейся задачи проходит молча.** При `missPolicy: "expire"` вхождение становится `skipped` без единого сообщения, а перенести его потом запрещено. Для продукта про избегание это самый важный момент, и он невидим.
5. **Сигналы `avoidance.ts` некуда доставлять.** Они живут один ход в контексте модели; ни напоминания, ни брифинги их не читают, поэтому «замечаю, что ты это откладываешь» работает только если пользователь сам написал про эту задачу. Блокеры (`occurrence:blocker`) пишутся и почти не читаются.
6. **Разовая задача с прошедшим временем не имеет перехода вообще** (`missPolicy` валиден только для повторов) и висит «просроченной» вечно. Один `missPolicy` на все задачи убрал бы особый случай.
7. **`set_reminder` на существующей задаче без даты отказывает** — путь `changeReminderInTx` целиком occurrence-ориентирован. При создании напоминание уже ложится на день проверки.
8. **Ярлык повтора врёт:** `recurrenceLabel` не показывает исключённые даты и несколько времён в день. Правка серии молча пересоздаёт все будущие вхождения, и отчёт об этом не говорит.
9. **Три формата времени на одну occurrence** (карточка с поясом, строка списка без пояса, `todayLine`) и «просрочено» в трёх разных смыслах: `/tasks`, `/today` и дайджест считают по-разному. «Главное» на `/today` и в утреннем дайджесте выбирается разными сортировками.
10. **Онбординг держится на кнопках:** шаги «дайджесты / тихие часы / обзор» без `pendingInput`, набранный текст уходит в модель, `onboardingCompletedAt` остаётся пустым, а тихие часы уже включены в `Europe/Kyiv` до подтверждения пояса.
11. **Навигация:** 25 слов команд, 13 в меню Telegram, 8 в `/help`; карточки после действия без футера; две кнопки «назад» сбрасывают выбранный фильтр.
12. **Разговор:** чекпоинт после пяти вопросов считается и выбрасывается рендером; `kind: "context"` против `note/decision/preference` — развилка без объяснения и без метки в `/context`; чувствительная память после сохранения не показывается нигде.
13. **Отказы:** пользователь в `deletion_pending` получает «бот приватный» вместо подсказки `/restore`; текст в группе игнорируется молча.

### Обновление зависимостей (2026-09-05)

`eslint 10`, `rxjs 7.8.2`, `NestJS 12` (common/core/platform-express/testing) и `TypeScript 6.0.3` — прогнаны check, e2e, coverage и сборка образа, правок в коде не потребовалось.

`TypeScript 7` отложен сознательно: `typescript-eslint@8.69` отказывается запускаться на нём («typescript-eslint does not support TS 7.0», поддержка ожидается для 7.1, typescript-eslint#10940). Единственный обходной путь — держать в дереве два компилятора (TS 7 для сборки, TS 6 для линта), то есть две разные системы типов на один код. Вернуться, когда typescript-eslint выпустит поддержку.
