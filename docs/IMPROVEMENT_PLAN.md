## 0. Как работать по этому плану

- Один пункт (`Pn.m`) = одна ветка от `agent-flow-v2` (или от `main` после её слияния), один PR, один осмысленный коммит. Не объединяй пункты из разных фаз в один PR.
- Перед началом пункта прочитай указанные файлы целиком, не только цитируемые строки.
- После каждого пункта: `npm run check`. Если пункт трогает SQL, репозитории, миграции или транзакции: ещё `npm run test:e2e` (нужен Docker).
- Новая миграция = новый номер `00NN_*.sql`; существующие миграции не редактировать.
- `.env` не читать и не менять. Конфигурация только через `.env.example` и `src/config.ts`.
- Соблюдай инварианты из `AGENTS.md`: workspace-изоляция, консент на границе провайдера, мутация + журнал в одной транзакции, логи без текста сообщений.
- Если пункт меняет поведение для пользователя или оператора, обнови `README.md` / `MANUAL_ACTIONS.md` / `docs/DEPLOYMENT.md` в том же PR.
- Порядок фаз обязателен для фаз 0 и 1. Внутри остальных фаз пункты независимы, если не указано «после Pn.m».
- Каждый пункт имеет критерий приёмки. Пункт не закрыт, пока критерий не выполнен и не проверен тестом или командой.

## 1. Что сохранить (это работает хорошо)

- `src/core/` чистый: не импортирует ничего снаружи, тестируется отдельно. Не ломать.
- Транзакционная модель действий: один `action_group` + журнал + блокировки `FOR UPDATE ORDER BY id` в одной транзакции, внешних вызовов внутри транзакций нет.
- Контракт агента v2 (`src/core/ai-contract.ts`): 9 действий, короткие id `t1/g2/m3`, один `intent`, риск считает сервер.

- `src/core/applied-report.ts`: отчёт только по реально сохранённому, с датой до/после.

- Никакого `parse_mode` в Telegram: класс ошибок экранирования отсутствует.

## Что осталось

**Инфраструктура (проверено на сервере 2026-09-05):**

1. **Off-site бэкапы.** Локальный стопгап работает: ключ в `/home/deploy/ipsycho-secrets/backup.key`, cron 03:15 (7 дневных + 4 недельных), первого числа — проверка восстановления в одноразовый контейнер. Проверено вживую (`backup_ok … offsite=no`, `restore_check_ok … tables=26`). Но копии и ключ шифрования лежат на той же машине, что база: потеря диска — потеря всего. Нужен bucket S3-совместимого хранилища и ключи; дальше достаточно дописать `S3_BACKUP_URI` в строку cron.
2. **Сверка цен провайдера.** `AI_PRICING_JSON` помечен `revision: 2026-09-05`. При смене модели или тарифа расчёт молча останется по старым числам.
3. **Ручные проверки `MANUAL_ACTIONS.md`** — требуют живого Telegram-аккаунта.

**UX (аудит 2026-09-05). Закрыто переработкой продукта того же дня** (пул недели, утренняя и недельная карточки, удаление вечернего обзора и догона, разбор абстрактной задачи — см. `docs/AGENT_FLOW.md` §9и): молчаливый пропуск и недоставленное избегание больше не актуальны — вместе с самим механизмом ушли и блокеры; форматы времени и «просрочено» остались как были.

**Осталось по UX:**

4. **Разовая задача с прошедшим временем** не имеет перехода вообще и висит просроченной вечно. Один `missPolicy` на все задачи убрал бы особый случай.
5. **`set_reminder` на существующей задаче без даты отказывает** — путь `changeReminderInTx` целиком occurrence-ориентирован. При создании напоминание уже ложится на день проверки.
6. **Ярлык повтора врёт:** не показывает исключённые даты. Правка серии молча пересоздаёт все будущие вхождения, отчёт об этом не говорит.
7. **Три формата времени на одну occurrence** и «просрочено» в трёх смыслах: `/tasks`, `/today` и утренняя карточка считают по-разному.
8. **Онбординг держится на кнопках:** шаги после пояса без `pendingInput`, набранный текст уводит в модель; тихие часы включены в `Europe/Kyiv` до подтверждения пояса.
9. **Навигация:** карточки после действия без футера; две кнопки «назад» сбрасывают выбранный фильтр.
10. **Разговор:** чекпоинт после пяти вопросов считается и выбрасывается рендером; чувствительная память после сохранения не видна нигде.
11. **Отказы:** пользователь в `deletion_pending` получает «бот приватный» вместо подсказки `/restore`; текст в группе игнорируется молча.

**Решения приняты (2026-09-05):**

- **Привычек нет.** Режим привычки убран целиком: повторяющаяся задача без конечной даты и есть привычка.
- **Кнопки «Начал» нет** вместе с состоянием, которое она ставила. `in_progress` остался значением enum и читается у старых строк, но новых не появляется, поэтому карточка у всех вхождений одна.
- **Память и цели остаются** действиями модели. `plan` тоже: задача не может сослаться на цель, созданную в том же сообщении, — без него «цель и первые дела» распались бы на два хода.
- **Пауза серии** предлагается только у повторов без конечной даты: у серии со сроком пауза только теряет даты.
